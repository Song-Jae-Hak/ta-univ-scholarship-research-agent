# 인수인계 — 타대학 장학 제도 조사 보고서 (HWPX 빌드용 콘텐츠 패키지)

## 1. 이 패키지가 무엇인가
확정된 보고서 기획(`report/목차_스토리라인.md`의 Ⅰ~Ⅶ장 구조와 편집 원칙)을, **`pnu-hwpx-report` 스킬이 그대로 빌드할 수 있는 콘텐츠 JSON**으로 정리한 것이다. 본문 내용은 `research/01~05`의 근거로만 채웠고, 서식·로고 결정은 포함하지 않는다.

- 콘텐츠 JSON: `report/handoff/보고서_콘텐츠.json` (UTF-8, 7개 섹션 + 붙임 2개, 표 6개)
- 이 문서: `report/handoff/README_인수인계.md`

## 2. 빌드 방법 (다음 세션이 실행)
프로젝트 루트(`타대학 리서치 에이전트/`)에서:

```
python pnu-hwpx-report\scripts\build.py -c report\handoff\보고서_콘텐츠.json -o report\handoff\타대학_장학제도_조사보고서.hwpx
```

1. 실행 로그에서 `PASS: true` 를 확인한다.
2. 생성된 `타대학_장학제도_조사보고서.hwpx` 를 **한컴오피스 한글로 열어 육안 검증**한다(표 6개, 붙임 2개, 각주 렌더링 확인).
3. `메타.출력_파일명` 은 `타대학_장학제도_조사보고서.hwpx` 로 지정되어 있다(`-o` 인자와 일치시킬 것).

## 3. 근거 파일 위치
- 확정 기획(블루프린트): `report/목차_스토리라인.md`
- 근거 원천 5종:
  - `[01]` `research/01_policy.md` — 정부 정책
  - `[02]` `research/02_univ_national.md` — 거점국립대
  - `[03]` `research/03_univ_private.md` — 주요 사립대
  - `[04]` `research/04_univ_special.md` — 특수대학
  - `[05]` `research/05_disclosure.md` — 공시 지표
- 본문의 근거 태그 `[01]~[05]` 는 위 매핑을 그대로 따른다.

## 4. 보존해야 할 편집 원칙 (내용 수정 시 반드시 유지)
1. **단일 주제 축(헤드라인):** "재원의 65%가 국가장학금(3조2,858억원) → 대학 자체 노력은 총액이 아니라 교내장학금 비중(31.4%, 1조5,872억원)으로 봐야 한다." 전 장이 이 축으로 수렴.
2. **근거 태그:** 모든 수치 문장 끝에 `[01]~[05]`.
3. **미확인 표기:** 확인 못한 값 `(미확인)`, 2차 출처 값 `(2차출처)`. research에 없는 사실은 추가하지 말 것.
4. **혼동 금지 2건(본문 주석으로 명시됨):**
   - (a) 공시 5조540억원(2024회계연도 실지급) ≠ 정책 5조1,161억원(2026 예산).
   - (b) 1인당 장학금(사립 403.4만 > 국공립 313.3만) ≠ 1인당 교육비(국공립 2,592.5만 > 사립 1,838.6만). 방향 반대, 혼용 금지.
5. **대학 우열은 유형 단위로만.** 개별 대학 실명은 '제도 예시'로만, 실명 순위표 금지.
6. **부산대(Ⅵ장):** 맨 앞 이해상충 고지 주석 → 확인/미확인 동일 잣대 공개. 우호적 부각 금지.
7. **로고·서식(제목 블루선, 폰트, 표 머리행 색, 각주 스타일, 최종 파일명 등)은 빌드 세션이 최종 결정한다.** 본 JSON은 콘텐츠(문구·표 데이터·구조)만 담고 서식 자원은 담지 않는다.

## 5. 콘텐츠 JSON 스키마 요약 (pnu-hwpx-report 규격)
- **최상위:** `메타`{`출력_파일명`}, `회차`, `제목`, `날짜`, `발신1`, `발신2`, `섹션`[], `붙임`[]
- **섹션 원소:** `{ "표제": "...", "항목": [ ... ] }`
- **항목 원소(각 dict, 키 1개):**
  - `{"글머리": {"라벨":"..","내용":".."}}` → ◦ **(라벨)** 내용
  - `{"글머리": "라벨 없는 일반 글머리"}`
  - `{"하위": "- 하위 글머리"}`
  - `{"주석": "※ 단서"}`
  - `{"여백": true}` (빈 줄)
  - `{"표": { "머리":[...], "폭":[...], "정렬":["C"|"J"|"L", ...], "합계행": true, "행":[[셀, ...], ...] }}`
- **붙임 원소:** `{"번호":1, "제목":"...", "항목":[ ... ]}` (본문 `항목`과 동일 구조)
- **표 규칙:**
  - `폭` 합계는 반드시 **45352(HWPUNIT)** 에 맞춘다. (본 JSON의 표 6개 전부 45352 검증 완료)
  - `정렬`·`합계행`·`폭` 은 선택. `합계행: true` 는 마지막 행을 합계 행으로 서식.
  - 셀은 문자열, 또는 여러 줄이면 문자열 리스트 `["줄1","줄2"]`.
- **JSON 형식:** 유효한 UTF-8, 큰따옴표, 트레일링 콤마 금지. (검증 완료)

## 6. 검증 상태 (본 세션에서 확인)
- JSON 파싱 성공(재로딩 OK), 섹션 7개 / 붙임 2개.
- 표 6개 모두 `폭` 합계 = 45352, 머리-행 열 수 일치.
- 표 위치: Ⅱ(국가장학금 Ⅰ유형 구간·2026 예산 2개), Ⅲ(유형별 비교 1개), Ⅳ(재원 구성·1인당 지표·데이터 신뢰도 3개).
- `pnu-hwpx-report\` 폴더는 열지 않았으므로 `build.py` 인자·`PASS` 판정은 빌드 세션에서 실제 실행으로 최종 확인 필요.
